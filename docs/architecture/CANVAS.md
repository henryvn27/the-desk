# Canvas

The Desk owns canvas identity, assignment association, timestamps and optimistic revisions in SQLite schema 5. `packages/canvas/scene.ts` is the versioned scene boundary; the initial renderer adapter uses Excalidraw 0.18.1. This scene format preserves engine fields and original ink, but a future renderer replacement will require an explicit conversion, not a package swap.

The renderer loads on demand. Fonts are packaged locally. Embedded web content and Excalidraw AI are disabled; browser navigation remains denied by the desktop shell. Scene validation bounds element count and serialized bytes, rejects embedded content and validates supported raster data URLs. Main validates commands again. Full scenes are fetched separately from the frequently refreshed snapshot.

Edits debounce into serialized writes. Saves compare revisions and fail on a stale version. Canvas Close and native window close/Quit wait for pending writes; validation or save errors keep the editor open. A narrow trusted close IPC retries the original native Quit intent after the renderer flushes. Forced process termination during the debounce interval can still lose the most recent unsaved action; crash-recovery journaling is not implemented. A stale editor preserves stored work and offers Save recovery copy and close. The validated scene is inserted as a separate Canvas without modifying the original revision. Library exposes the copy beside the assignment. If new edits arrive while the copy is saving, the editor stays open rather than discarding them. Recovery copies preserve embedded images; automatic merging is not implemented.

Verified scope: desktop ink, arrow, rectangle, undo/redo, close/reopen, exact stored scene through app restart; domain tests cover stale-write rejection and scene validation. PNG export and cancellation are exercised in the installed app with an injected native-dialog result; the written PNG is visually inspected. Main validates size/header/dimensions and owns the user-selected destination. Text and PNG import now survive save/close/app restart in the installed macOS smoke, with exact scene and embedded image bytes preserved. The image picker result is injected because Chromium File System Access does not emit a Playwright filechooser event; native image-picker interaction remains unverified. Excalifont loads under the local-only CSP. Upstream font registration also lists CDN fallbacks, which CSP blocks; no external font access was enabled. PDF annotation, paged mode, handwriting recognition, shared Lens primitives, additional Canvas tool behavior and interactive Windows parity remain unverified or unimplemented. The upstream toolbar is not blanket acceptance evidence.

Dependency overrides update vulnerable pinned nanoid/lodash-es versions; npm audit reports zero vulnerabilities after the overrides. Upstream Radix peer ranges emit React 19 warnings despite Excalidraw's React 19 peer support; local runtime checks pass, and broader regression coverage remains required.

Canvas source links are optional UUIDs in the domain scene envelope, preserving old scenes without a migration. Main validates linked source existence before saving or making a recovery copy. The Sources panel reads the original Library text beside the drawing. Unlinking changes the Canvas reference only; it does not delete Library material. The current source reader supports the existing pasted-text source type; PDF/web source ingestion remains separate unfinished work.

Pen and Highlighter are Desk controls over the same Excalidraw freedraw primitive. Pen restores dark opaque width-2 ink; Highlighter uses yellow width-8 ink at 35 percent opacity. Scene persistence retains their stroke styles, and both participate in engine undo/redo. These are explicit presets; advanced pressure/tilt behavior and the rest of the tool acceptance matrix remain separate verification work.

Math blocks use lazy local MathJax 4.1.3 with explicit base/AMS TeX packages and the bundled TeX SVG font. Inputs are capped at 2,000 characters, parser expansion is bounded, and output dimensions are capped. The generated self-contained SVG is rasterized to a 2x PNG for the Canvas adapter; `customData.deskMath.latex` preserves editable normalized LaTeX in the domain-validated scene. Editing replaces the image while retaining identity and position; old image bytes remain available for undo. No renderer secrets or remote inference are involved. The configuration follows MathJax direct-module and self-contained SVG guidance: https://docs.mathjax.org/en/v4.1/server/direct.html and https://docs.mathjax.org/en/v4.1/web/convert.html.

Math toolbar undo/redo, invalid input, insertion and editing after restart are tested. Electron native Edit-menu accelerators previously consumed Cmd+Z before it reached the renderer. The main process now lets Z/Y edit shortcuts reach renderer editors, and Canvas handles them globally while its Math dialog is closed. Writable fields retain their own editing path. Native Edit-menu actions send a validated undo/redo event to the window supplied with the menu callback. The renderer routes Canvas actions to its accessible history buttons and writable-field actions to text editing. Installed macOS menu selections have been exercised with saved-scene assertions; the first selection after automation activation had no observed effect, so focus-transition behavior remains under investigation. This follows Electron before-input-event/setIgnoreMenuShortcuts guidance: https://www.electronjs.org/docs/latest/api/web-contents#event-before-input-event. Math is a raster-backed Canvas object, so double-click uses the engine image controls; use Math to edit its LaTeX. Broad LaTeX-package compatibility and handwriting conversion are not claimed. The lazy math chunk is about 2.8 MB before gzip; the build warning remains visible.
